# DMC 阶段 07C：DMC 专用快速环境驱动（吞吐最后杠杆，差分验收）

日期：2026-10-25 · 状态：待执行（依赖 07A/07B 已合入；完成后合并构建 Gate L 重跑交付）

## 依据（07A 剖析实测，推翻了"枚举是瓶颈"的原假设）

- 采集循环 **53~66% 耗时在 `EnvBatch.step` 内部**：每个环境 token 步做事务性 clone、协议急切校验、候选行双重重建、**四个座位全量通道编码**；
- V1 规则引擎合法枚举被适配器每 token 步调用约 6 次（大头），而 sampler 侧枚举只占 2.5%；
- 07A 组合外推 Kaggle 吞吐仅 1.0~1.15 局/s；要把 2.5 亿样本的日历从 ~28 周压到 ~14 周，必须砍适配器冗余。

## 任务：新建 `guandan_marvel/dmc/env_fast.py`（DMC 专用薄驱动）

**不改 `guandan/` 规则引擎、不改 `EnvBatch` 本身**——新代码全部在 `dmc/` 内，以差分等价换性能：

1. **只编码行动座位的 512 通道**（DMC 决策只读行动者通道；其余座位通道在候选确定后由 env 推进时再算或不算）；
2. **候选行只建一次**：DMC sampler 已从枚举器拿到完整候选 token 序列，驱动在提交 token 时不再走"全行重建+逐行匹配"（现在 `_action_row_for` 每步扫全合法行）；
3. **跳过已知合法前缀的事务性 clone**：sampler 提交的是枚举器产出的合法序列，逐 token 重验证是冗余；驱动在序列提交边界做一次终态校验即可；
4. 终局奖励/名次/贡还语义完全复用现有协议对象，不重写规则。

## 验收标准（全部硬性）

1. **差分模糊测试（核心）**：≥200 局随机对局，快速驱动 vs 参考 `EnvBatch` 驱动，以下内容**逐字节一致**：每步行动座位观测 token 流、行动座位通道、合法行动序列、所选动作执行后的全座位公开状态哈希、终局 rewards/ranking/outcome。任何分歧立即 fail-closed，禁止容差。
2. 本机采集吞吐：同剖析配置（07A 基线 0.527 局/s 采集）**≥1.5x（≥0.79 局/s）**； REPORT 给出剖析前后热点对比；
3. `pytest tests/dmc -q` 全绿 + 差分测试纳入常规套件；
4. 同 seed 确定性保持；评估路径（`tools/dmc_gate_l/evaluate.py`）切换到同一快速驱动（训练/评估必须同分布）；
5. Gate L 交付的 plan 显式声明启用快速驱动 + 差分测试版本号。
