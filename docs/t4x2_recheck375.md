# Kaggle T4×2：iter375 同集复测（只评估，零训练）

## 这次解决什么

上一轮已完成250→500，但375和500用了不同开发集，不能直接把两个胜率当同集学习曲线。本包把 **375放到500用过的128副开发牌局**上：

- 复用已有250对rule、500对rule、500对250结果，不重跑整套基线。
- 新增375对rule、375对250、**375对500直接对战**，更直接地区分检查点。
- 消除0/2、1/3轮换的重复：同质队友、temperature=0时只跑两个唯一整队分配。
- 每个评估臂都分给两张卡，不再一张卡全跑轻任务、另一张全跑双模型重任务。

**本包不会训练、不改模型权重、不启动对手池，不运行FableDan，不消费最终holdout。** 375只是已有评估快照，不把它伪装成完整训练恢复状态。

## 上传：只用两个文件

1. 新建Kaggle Dataset，上传 `guandan_recheck375_payload_v1.bin`。
2. 导入Notebook `guandan_recheck375_v1.ipynb`，挂载上述Dataset。
3. Accelerator选择 **GPU T4×2**；Internet可以关闭。
4. 首次运行不用改代码，Run All。

不要上传整个项目，不要手动解压 `.bin`，不要混用continue500/旧pilot Notebook。本包已包含三个原模型、原源码、原Linux native、同集发牌、历史结果和新评估驱动，不需要另外上传旧结果ZIP。

## 实际新增多少工作

- 同一套128副牌 × 2个唯一队伍分配 × 3个375对战臂 = **768场新增棋力评估**。
- 另有 **24场旧结果重放校验**：4副牌覆盖原贡还场景 × 2分配 × 3个已知对战臂，用于验证当前Kaggle环境与旧缓存行为一致，不计入新增统计信息。
- 全新完整运行最多 **792场实际GPU游戏**，不是1536场旧基线重新跑。
- 375前24场是冒烟，**已经包含在768场中**，通过后只跑余下744场，不重复计数。
- 缓存保留768条唯一记录，来自旧1536条实际记录。构建与启动时都会验证全部重复轨迹以及四记录→两分配的胜率、得分和聚类区间等价。

旧的128副牌仍是128个独立统计单位，两个整队分配不是两副独立牌局。不能仅改轮换范围而仍按4做分母；本包使用独立版本的新协议和动态聚类均值，旧结果等价校验必须先通过。

## 执行门槛与日志

1. 输入SHA、Notebook配对、三个模型迭代/权重/来源、缓存1536条任务与终局语义检查。
2. 绑定原native绝对路径、Python/PyTorch和双T4；拒绝错误环境、冲突旧源码，不改checkpoint头、不重编译或CPU回退。
3. 真实重放24场已知结果，核对动作轨迹hash、终局排名/奖励/步数。失败立即停止，不开始375大评估。
4. 375先完成24场真实冒烟，确认各对手和贡还场景能结束，失败不跑后续744场。
5. 其余对局按各臂均衡分片；若一名worker失败，立即终止同伴并保存可核验的已完成进度。
6. 全套完成后才给同集比较，统计INCONCLUSIVE是正常结果，不等于程序错误。

保留逐局记录、计划/模型/任务hash、GPU分配、终局与引擎计数、每卡耗时、利用率/显存、冻结权重不变验证和错误traceback。训练局数和optimizer更新数始终明确为0。

本包仍使用已验证的逐局引擎，不冒险同时重写批量推理；修复了明确的重复和分片浪费，但不承诺100%GPU利用率。

`/kaggle/working/guandan_t4x2_combo_v1/source/guandan-marvel-source`

这是为了保留真实后端身份，不是误跑旧训练。新日志/报告在：

`/kaggle/working/guandan_recheck375_v1`

原路径已有文件只在源码与二进制逐字节验证一致时复用；冲突则拒绝，绝不覆盖旧文件或改hash骗过加载器。建议使用新的Kaggle会话；若平台更新了Python/PyTorch，本包会前置报错，而不是跑到后面才发现缓存不可比。

## 时间预算与恢复

按上一轮逐局耗时，预计约半小时至一小时，**不是速度保证**。完整安全上限90分钟，保留5分钟收尾预算。缓存重放与375冒烟各自最多15分钟；平台不足或技术错误会停止并输出已验证进度。

下载 `guandan_recheck375_results.zip`。技术状态以result.json为准：预算停止会明确标为 `budget_stopped`，不把Notebook脚本成功结束等同于评估已完成；技术故障则明确报错。

- 如果未跑完：把这个结果ZIP上传为另一个Dataset；若Kaggle自动将ZIP解压，填入包含 `resume_manifest.json` 的目录也可以，不要求挂载后仍有ZIP文件。使用 **同一份payload和Notebook**，在代码开头将 `RESUME_RESULTS_ZIP` 填为挂载后的绝对路径，并使用新的RUN_ROOT。
- 只续跑逐局校验通过但尚未完成的375任务。缺失任务会重新均衡到两张卡；不从零开始。
- 恢复仍做少量缓存环境重放；若375全套已经完成，则只重建报告，零新增对局。
- 这里填的是本包的整个结果ZIP或其被Kaggle展开的目录，**不是旧continue500结果或latest_recovery.zip**。
- 不能在已有RUN_ROOT上直接反复Run All。先下载输出，再用新路径/新会话，避免串日志。
- 外部强制断电、进程被平台杀死、文件损坏无法绝对避免；逐局落盘与正常失败收尾能减少损失，不能保证未落盘工作可恢复。

## 输出怎么看

- `result.json`：技术状态、复用/新增/重放/实际尝试次数，训练更新=0。
- `checkpoint_comparison.json`：六个同集对战臂、胜率、平均队伍得分、按牌局聚类95%区间，以及rule配对增量。
- `REPORT.md` / `report.html`：人读摘要与恢复说明。
- `cache_equivalence.json`：旧四轮换→两个唯一队伍分配的完整证明。
- `model_validation.json` / `backend_identity.json`：模型和环境身份。
- `cached_unique_games.jsonl`：明确标注为旧缓存，不冒充新跑。
- `new_games.jsonl`：已核验的375新增对局，恢复依据。
- `phases/`：两卡任务、逐局结果、console与状态；`telemetry.jsonl`、`performance.json`记录实际资源与耗时。
- `resume_manifest.json`：结果文件hash和计划绑定，防止跨包错误恢复。

三模型同集比较只是 **重复使用旧开发集的事后诊断**。即使375看起来更好，也不自动晋级，不宣布超过FableDan；应再做新的确认牌局，之后才决定学习率/早停或历史对手池的单变量实验。

本地验证范围见 `LOCAL_VALIDATION.json`；最终包检查见 `ARTIFACT_QA.json`。本机CUDA接线测试不是目标双T4认证，目标机的真实门槛仍需通过。
